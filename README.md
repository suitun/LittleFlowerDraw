# 小花绘（LittleFlowerDraw）

让小花帮你画

版本：**0.1**。MaiBot 清单要求三段式版本号，因此 `_manifest.json` 中使用 `0.1.0`。

个人自用的 QQ + SnowLuma 角色参考图库。已实现附图或引用图片登记、同名覆盖、按名查看，以及可在 WebUI 热更新的触发词和回复文案。绘图替换、用户等级和限额后续再开发。

## 角色库怎么用

**角色库全局共享**：当前机器人实例中的所有群和用户使用同一份图库，任何人都可以登记、查看或覆盖同名角色。覆盖后，其他群查看该角色也会得到新图。

| 操作 | 消息示例 | 图片来源与结果 |
| --- | --- | --- |
| 登记角色 | `小花小花这是 角色1`，同时附图 | 保存本条消息中的图片，回复「小花记住角色1了喵～」 |
| 引用登记 | 引用一条有图的消息，再发送 `小花小花这是 角色1` | 读取被引用消息的图片后登记 |
| 同名覆盖 | 再次发送登记消息并提供图片 | 完整替换该角色的图片组，回复已记住新模样 |
| 查看角色 | `小花小花我要看角色1` | 在当前聊天发回该角色的所有图片 |

登记模板中的空格可以省略，也支持 `小花小花这是角色1`。一次消息可以保存多张参考图；相同内容去重后按顺序保存。同名覆盖不是追加图片，而是替换整组图片。

有当前附图时优先使用附图，不混入引用图；没有附图才读取一层引用，不递归读取引用的引用。先查宿主历史，旧图片不在历史中时通过 SnowLuma 公开接口查询。图片不可用时给出提示，不会假报入库成功。

匹配图库触发模板的请求由插件处理，不再让聊天模型额外回复；其他消息正常放行。机器人自己的消息不触发图库。

## WebUI 热配置

在 WebUI 选择正确的机器人实例，打开「小花绘」的插件配置：

- **角色库触发词**：修改登记和查看的模板列表，可添加多条别名。每条必须且只能有一个 `{角色名}`，角色名前需要固定触发文字。
- **角色库回复文案**：分别设置首次入库、同名覆盖、查看、未找到、缺图、错误等回复。支持 `{角色名}` 和 `{图片数量}`；查看前的文案可留空，只发图片。
- **角色库限制**：调整角色名长度、单次图片数、每张与总大小、像素数限制。

例如将登记模板改为 `记住 {角色名}`，成功回复改为 `小花收好{角色名}的{图片数量}张图啦喵～`，保存后新消息立即使用新配置，无需重启插件。已经接收并排队的请求继续使用接收时的配置。

不支持的占位符、重复触发模板或格式化指令会被配置校验拒绝。触发模板按完整消息匹配，角色名保留大小写和内部空格，首尾空白会去掉。

## 环境与安装位置

- 当前验证环境：MaiBot `1.4.3`、`maibot-plugin-sdk` `2.22.1`。
- 清单兼容范围：宿主 `1.4.3` 至 `1.4.99`，SDK `2.22.1` 至 `2.22.99`。
- 使用 MaiBot 自身的 Python 环境；Pillow 和 Pydantic 依赖已在清单声明，由宿主处理安装与兼容性检查。
- 群聊联调需要正常工作的 QQ 适配器和已放行的测试群。

插件必须放进**正在运行的机器人实例**的 `plugins` 目录。多实例宿主的源码根目录不等于机器人实例目录：

```text
MaiBot 工作区/
├── host/                         # 宿主与机器人注册表
├── bots/
│   └── <机器人 ID>/
│       ├── config/
│       ├── data/
│       ├── plugins/
│       │   └── LittleFlowerDraw/  # 本插件的实体 Git 仓库
│       └── temp/
└── plugins/                      # 不作为上述机器人的插件安装位置
```

旧式单实例部署直接使用该实例根目录下的 `plugins/LittleFlowerDraw`。本项目使用实体目录，不使用目录联接或符号链接；WebUI 插件索引会拒绝解析到插件根目录之外的目录。

首次安装时，在目标机器人实例目录执行：

```powershell
git clone https://github.com/suitun/LittleFlowerDraw.git plugins/LittleFlowerDraw
```

已经存在本仓库时直接在当前目录开发，不再克隆第二份。仓库结构：

```text
LittleFlowerDraw/
├── _manifest.json     # 名称、版本、依赖、能力与兼容范围
├── plugin.py          # 生命周期、消息入口、后台处理与回复
├── settings.py        # WebUI 配置模型
├── role_patterns.py   # 触发与回复模板
├── role_messages.py   # 附图、引用与图片校验
├── role_store.py      # SQLite 事务存储
├── AGENTS.md          # AI 协作开发约定
├── README.md
├── LICENSE
├── .gitignore
├── .gitattributes
├── assets/            # 随源码维护的固定素材
└── tests/             # 存储、图片来源、模板与 SDK 集成测试
```

## 首次启用与验证

1. 打开 WebUI，选中正确的机器人实例，进入插件管理并刷新页面，查找「小花绘」。
2. 插件默认禁用，在插件管理中启用。Runner 根据配置模型生成本地 `config.toml`。
3. 在测试群发送 `/小花绘`，查看当前登记和查看触发模板。
4. 发送 `小花小花这是 测试角色` 并附图，等待入库成功回复；再发送 `小花小花我要看测试角色`，确认图片能发回。
5. 再用另一张图片登记同名角色，确认收到覆盖回复；到另一个群查看，确认得到新图。
6. 引用一条有图的消息登记另一个角色，验证真实 QQ 引用链路。
7. 在 WebUI 修改触发词和回复，保存后直接使用新词，确认无需重启就生效。
8. 若新增目录未被运行中的实例发现，先查看该实例日志；必要时通过 WebUI 重启该机器人实例后再检查。

| 命令 | 作用 |
| --- | --- |
| `/小花绘` | 查看插件状态 |
| `/小花画图` | 兼容原状态命令 |
| `/lfdraw` | 英文别名 |

## 日常开发流程

1. 在**实例的 `plugins/LittleFlowerDraw` 仓库内**工作。先读 `AGENTS.md`、清单、配置模型和相关接口文档。
2. 查看工作区，已有改动先确认归属。工作区干净且需要获取远程更新时使用快进拉取：

   ```powershell
   git status --short --branch
   git pull --ff-only
   ```

3. 按需求修改插件源码。配置项在 `config_model` 中声明；依赖和宿主能力在清单中声明。
4. 做基础检查，再用宿主 SDK 验证插件导入、组件注册和配置 Schema。下面两条 Python 命令只检查 JSON 和语法，不代表插件已经在 MaiBot 中加载成功：

   ```powershell
   python -m json.tool _manifest.json
   python -m py_compile plugin.py
   git diff --check
   ```

5. 在 WebUI 查看实际加载状态和日志。运行时支持源码与配置热重载；需要时手动重载插件。验证此次修改涉及的行为，确认全局角色共享正确且回复不会发到别的群。
6. 检查差异，仅提交本次相关文件，再同步仓库。按实际改动调整下面 `git add` 的文件列表：

   ```powershell
   git diff
   git add -- plugin.py settings.py role_*.py _manifest.json README.md AGENTS.md tests
   git diff --cached
   git commit -m "描述本次改动"
   git push origin main
   ```

本机在这个目录改代码，就是在修改运行实例读取的代码，不需要再次复制或从 GitHub 下载安装。

## 更新到另一台运行机器

1. 开发机完成检查、提交并推送。
2. 在运行机器对应的机器人实例插件目录执行 `git status --short --branch`。有本地源码改动时先处理，保留本地配置和数据。
3. 工作区干净后执行 `git pull --ff-only`，再在 WebUI 确认插件重新加载；必要时手动重载。
4. 检查配置能打开、命令能触发，以及本次更新涉及的功能和日志。

自用的 `main` 分支更新不需要创建 GitHub Release 或提交插件市场。`_manifest.json` 中的 `version` 在发布新插件版本时更新；`plugin.config_version` 只在配置结构发生变化时更新，两者不要求每次一起改。

如果需要撤销已经推送的某次改动，使用 `git revert <提交号>` 创建撤销提交，验证后再推送、重载。

## 配置、数据与权限

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `plugin.enabled` | `false` | 是否启用小花绘 |
| `plugin.config_version` | `0.2.0` | 配置结构版本；与插件版本分开维护 |
| `keywords.register_templates` | `["小花小花这是 {角色名}"]` | 登记和覆盖模板 |
| `keywords.view_templates` | `["小花小花我要看{角色名}"]` | 查看模板 |
| `replies.*` | WebUI 中显示各默认文案 | 各种结果的回复模板 |
| `library.max_name_length` | `64` | 角色名最大字符数 |
| `library.max_images` | `6` | 一次登记最多保存的不同图片数量 |
| `library.max_image_mb` | `8` | 每张图片最大 MB |
| `library.max_total_mb` | `12` | 一次登记总大小最大 MB |
| `library.max_pixels` | `40000000` | 单图最大像素数 |

`config.toml` 由 Runner 生成，新增配置字段由运行时补齐；当前源码的默认配置结构版本为 `0.2.0`，与插件版本 `0.1.0` 分开维护。已有安装可保留其运行时配置版本和值，新增字段使用默认值。用户通过 WebUI 修改配置，不提交到 Git。

使用 `send.text`、`send.image` 回复；`chat.open_session` 确保首条请求能建立聊天流；`message.get_by_id` 读取宿主引用历史；`api.get`、`api.call` 调用 SnowLuma 的公开消息和图片查询接口。

- `assets/`：需要随代码版本维护的固定素材。
- `self.ctx.paths.data_dir/roles.sqlite3`：角色名、首次创建者和图片内容。同名覆盖在单个事务内完成，失败会保留旧图；不会把角色名作为文件路径。
- `self.ctx.paths.runtime_dir`：临时图片、下载缓存和可重建文件。

本地配置、环境变量文件、日志、数据库和 Python 缓存均由本仓库 `.gitignore` 排除。

当前支持 PNG、JPEG、WebP、GIF。保存的是通过消息接口实际收到的图片，仍受 QQ 以及 MaiBot 入站图片压缩、体积和 IPC 限制影响，不承诺原始分辨率。网络图片仅从受支持的 QQ 图片 CDN 读取；同机的客户端本地图片路径只信任公开 `get_image` 接口返回的结果。

## 自动检查与真机联调

使用宿主 Python 环境运行：

```powershell
python -m unittest discover -s tests -v
```

测试覆盖附图与引用、跨群全局共享、覆盖与事务回滚、重启持久化、模板热更新、图片限制、重复消息、错误回复和后台任务清理。测试使用小图片和 SDK 测试替身，不建立模拟 OneBot 服务，也不会发送真实 QQ 消息；真实 QQ 验收按前面的步骤进行。

## 排查未显示或未加载

按以下顺序检查：

1. WebUI 是否选中了插件实际安装的机器人实例。
2. 该实例的 `plugins/LittleFlowerDraw` 是否为实体目录，且清单和 `plugin.py` 直接位于其中。
3. 名称是否为「小花绘」、ID 是否为 `suitun.little-flower-draw`，清单版本是否使用 `0.1.0`。
4. 清单兼容范围、依赖与 `capabilities` 是否通过实际环境校验。
5. 插件是否只是处于禁用状态，或重载失败后回滚；以实例日志和 WebUI 实际状态为准。

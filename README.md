# 小花绘（LittleFlowerDraw）

让小花帮你画

版本：**0.9**。MaiBot 清单要求三段式版本号，因此 `_manifest.json` 中使用 `0.9.0`。

个人自用的 QQ + SnowLuma 角色参考图库和绘图指令入口。WebUI 统一入口「小花绘」下规划了角色库、插件设置、回复配置、当前任务、任务历史、绘图 API 和提示词模板等模块；当前已实现角色库、插件设置、回复配置、三类绘图指令、OpenAI 兼容图片 API、持久任务队列、当前任务和任务历史。聊天指令支持管理员/所有人权限、群聊与私聊白名单、每人每指令次数限制。

## 角色库怎么用

**角色库全局共享**：当前机器人的所有群和用户使用同一份图库，任何人都可以登记、查看或覆盖同名角色。覆盖后，其他群查看该角色也会得到新图。

| 操作 | 消息示例 | 图片来源与结果 |
| --- | --- | --- |
| 登记角色 | `小花小花这是 角色1`，同时附图 | 保存第一张图片，回复「小花记住角色1了喵～」 |
| 引用登记 | 引用一条有图的消息，再发送 `小花小花这是 角色1` | 读取被引用消息的第一张图片后登记 |
| 同名覆盖 | 再次发送登记消息并提供图片 | 用新图片替换旧图片，回复已记住新模样 |
| 查看角色 | `小花小花我要看角色1` | 在当前聊天发回该角色的唯一图片，文字和图片合并为一条消息 |
| 角色列表 | `小花记得谁` | 回复角色库中的角色数量和全部名字 |
| 帮助 | `小花绘帮助` | 用一张图片汇总当前可用指令和模板 |
| 自由绘画 | `小花画星空`，也可只发 `小花画` | 不依赖角色库，可带参考图，也可以不带图；没写提示词时用兜底提示词 |

登记模板中的空格可以省略，也支持 `小花小花这是角色1`。每个角色只保存一张图片：一条消息附带多张图时只取第一张，其余忽略；同名覆盖是整张替换，不是追加。角色列表指令 `小花记得谁` 会返回当前角色数量与全部名字，空库有单独的可爱提示。帮助指令 `小花绘帮助` 会把当前配置的指令模板画成一张图片发送。

有当前附图时优先使用附图，不混入引用图；没有附图才读取一层引用，不递归读取引用的引用。先查宿主历史，旧图片不在历史中时通过 SnowLuma 公开接口查询。图片不可用时给出提示，不会假报入库成功。

匹配图库触发模板的请求由插件处理，不再让聊天模型额外回复；其他消息正常放行。机器人自己的消息不触发图库。

任意角色库或绘图触发模板开头可以加一个 `@`，表示这条关键词必须先 @ 机器人才能触发，例如 `@小花小花这是 {角色名}`。`@` 只是模板语法，不会参与关键词正文匹配；不加 `@` 的模板仍然可以直接触发。多人替换正文里的 `@角色名` 不受影响。

## 绘图指令

绘图指令和角色库一样走关键词 Hook，并共用权限、白名单和次数限制。三类指令都要求消息附带第一张图，或引用一条有图的消息作为参考图；角色必须已经登记进角色库。

| 类型 | 默认消息示例 | 图片顺序 | 提示词 |
| --- | --- | --- | --- |
| 单角色替换 | `变角色1 红色外套` 或 `角色1穿 红色外套` | 图1 参考图，图2 角色1 | 单角色基础提示词 + 额外提示词 |
| 双角色替换 | `角色1角色2一起穿 同框合影` | 图1 参考图，图2 角色1，图3 角色2 | 双角色基础提示词 + 额外提示词 |
| 多人替换 | `多人穿@角色1@角色2@角色3 游乐园` | 图1 参考图，后续依次是角色图 | 多人基础提示词 + 额外提示词 |

- 额外提示词可以省略；单角色和多人替换的角色名按空白或 `@` 分隔，建议不要包含空格。
- 双角色替换会把两个名字连写的部分按已登记角色名拆分，例如 `角色A角色B` 会拆成两个已存在的角色。
- 多人替换默认限制 3-8 个角色，可在插件设置中调整。
- 当前阶段已接通 OpenAI 兼容的图片编辑 API：参考图和角色图按顺序上传，结果图会发回聊天，并保存到插件目录的 `drawings/日期/` 下。
- 绘图请求会进入持久任务队列，提交后立即回复任务 ID；任务由后台 worker 按配置并发执行。
- 角色图在真正执行任务时读取最新版本；参考图在提交时保存一份，避免引用消息失效。
- 绘图 API 的 URL、Token、模型、尺寸和超时在「小花绘 → 绘图 API」中配置。

## 绘图 API

当前只支持 OpenAI 兼容的图片编辑接口，默认调用 `/v1/images/edits`：

- **API URL**：可填到 `/v1`，也可填完整 `/v1/images/edits`；程序会自动补全。
- **API Token**：以 `Authorization: Bearer <token>` 发送；Token 保存在 `data_dir/drawing_api.json`，不要提交或外传。
- **模型**：默认 `gpt-image-1`；可点「拉取模型」从接口的 `/v1/models` 查询，中转站不支持时仍可手动填写。
- **尺寸**：
  - `auto`：交给 API 自动选择。
  - `reference`：按参考图宽高比，从官方支持的 `1024x1024`、`1536x1024`、`1024x1536` 中选最接近的一档，不是直接使用参考图的任意像素尺寸。
  - 自定义 `宽x高`：每条边限制 256-2048 像素，总像素不超过 400 万；超出会被配置校验拒绝。
- **超时**：默认 180 秒。
- 多张图片以 `image[]` 字段按顺序上传：图1 参考图，后续为角色图。
- 兼容返回 `data[0].b64_json` 或 `data[0].url` 的接口；结果会发回聊天，并保存到插件目录的 `drawings/日期/` 下。上传图片优先保持原格式；只有总请求超过约 18MB 时才按比例压缩，给接口的约 20MB 限制留余量。
- 未配置 API、调用失败或返回图片无效时，会发送对应的错误提示；失败不计入次数。
- 任务数据、任务追踪、任务队列和任务历史已落地到本地 SQLite；具体见下方「任务队列」。

## 任务队列

任务存储：`data_dir/drawing_tasks.sqlite3`。自由绘画使用独立任务类型，不检查角色库；有附图/引用图时作为参考图，没有时走纯文生图，提示词为空时使用「自由绘画兜底提示词」，默认 `发挥创意`。

- 任务 ID 从 `0` 开始永久递增，删除历史不会回退。
- 状态：`queued`、`running`、`succeeded`、`failed`、`cancelled`。
- 每人同时只能存在一个 `queued` 或 `running` 任务；管理员同样受限。
- 任务提交成功后立即回复短消息，例如 `任务 #0 收到啦喵～前面还有 0 个。`
- 任务完成时用一条图文混合消息发送任务编号、短完成文案和结果图；是否 @ 发起人由「回复配置 → 任务完成」的开关控制，默认关闭。
- 角色图不冻结，任务真正调用 API 时读取角色库最新图片；参考图在提交时保存到 `data_dir/drawing_tasks/{ID}/reference.png`。
- 任务失败或取消时按任务 ID 幂等退还次数；成功不退。接口返回 HTTP 400（图片不合规）时，不展示上游长错误，改用「回复配置 → 图片不合规（400）」的短文案。
- 任务记录发起人的 QQ 号、群昵称和 QQ 昵称；旧版本任务没有昵称时 WebUI 回退显示 QQ 号。
- 当前任务和历史任务卡片直接显示参考图或成品图；详情弹窗展示大图和完整时间、昵称、提示词、模型等信息。
- 插件重启时，遗留的 `running` 任务标记为失败并退还次数，不自动重跑，避免重复计费。
- 历史终态任务支持 WebUI 单条/批量重试（生成新 ID）和批量删除；卡片上也有单独的删除按钮。重试会在原任务所在的群聊或私聊重新入队，并沿用原参考图、角色、提示词和发起人。
- 当前任务/历史任务卡片显示创建时间、开始时间、结束时间和用时。历史搜索中的纯数字按任务编号或 QQ 号精确匹配，`#编号` 也支持；文字才匹配昵称和角色名。
- 历史元数据默认保留 30 天，输出图默认保留 30 天，均可在插件设置中配置；设为 0 表示不自动清理。

队列配置在「小花绘 → 插件设置 → 任务队列」：

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| 同时执行任务数 | `1` | 可调大，最大 8 |
| 最多排队任务数 | `20` | `0` 表示不限 |
| 任务超时秒数 | `600` | 超时任务失败并退次数 |
| 队列轮询秒数 | `2` | 队列唤醒的兜底轮询 |
| 历史保留天数 | `30` | `0` 表示不自动清理 |
| 输出图片保留天数 | `30` | `0` 表示不自动清理 |
| 暂停领取新任务 | `false` | 当前执行中的任务继续完成 |

## WebUI「小花绘」

插件加载后，WebUI 侧栏的「插件扩展」中会出现「小花绘」入口，内部用模块导航切换：

- **角色库**：浏览角色卡片、按名称搜索、按名称或最近更新排序、分页；打开详情查看压缩预览、图片大小、登记者和时间；上传 JPEG/PNG/WebP 创建或替换图片；重命名、删除角色。
- **插件设置**：角色库和绘图触发词、图片限制、绘图基础提示词、任务队列、管理员 QQ、群聊/私聊白名单，以及每个指令的权限/次数/重置天数。
- **回复配置**：按角色库、绘图任务、权限提示分组管理；每种回复可以配置多条，触发时随机抽取一条；每张回复卡片都有「回复时 @ 对方」开关，默认关闭。
- **绘图 API**：配置 OpenAI 兼容图片编辑接口的 URL、Token、模型、尺寸和超时，支持多图参考。
- **当前任务**：卡片直接显示参考图，按 12 个一页显示，查看排队位置、阶段、发起人昵称，可取消排队中的任务。
- **任务历史**：卡片直接显示成品图或参考图，按 20 个一页显示，支持按状态/任务编号/QQ/昵称/角色筛选、详情大图、单条重试和批量删除/重试。
- **提示词模板**：已预留入口，后续模块继续接入。

WebUI 只提供压缩预览（列表 160px 缩略图、详情最大 1280px），不提供原图下载，也不支持在 WebUI 上传 GIF；已有 GIF 角色仍可在 QQ 中查看。通过 WebUI 新建或替换图片时，服务端仍校验格式和文件体积，不再限制像素数。

## WebUI 设置

插件配置页只保留是否启用和配置版本；触发词、图片限制、绘图基础提示词、任务队列、权限和白名单在「小花绘 → 插件设置」中维护，回复文案在「小花绘 → 回复配置」中维护，保存在 `data_dir/webui_settings.json`。

回复配置按模块分栏：角色库回复、绘图任务回复、权限提示文案。每种回复是一个列表，可以添加多条候选文案；实际触发时随机抽取一条。每张回复卡片可以单独开启「回复时 @ 对方」，默认关闭；开启后文字回复会变成 @ + 文本的混合消息，查看角色的文字和图片也会合并在同一条消息里。旧版单条字符串会自动迁移成一条候选，不会丢失现有配置。

例如将登记模板改为 `记住 {角色名}`，成功回复改为 `小花收好{角色名}啦喵～`，保存后新消息立即使用新配置，无需重启插件。已经接收并排队的请求继续使用接收时的配置。

不支持的占位符、重复触发模板或格式化指令会被配置校验拒绝。触发模板按完整消息匹配，角色名保留大小写和内部空格，首尾空白会去掉。

## 环境与安装位置

- 当前验证环境：MaiBot `1.4.3`、`maibot-plugin-sdk` `2.22.1`。
- 清单兼容范围：宿主 `1.4.3` 至 `1.4.99`，SDK `2.22.1` 至 `2.22.99`。
- 使用 MaiBot 自身的 Python 环境；Pillow 和 Pydantic 依赖已在清单声明，由宿主处理安装与兼容性检查。
- 群聊联调需要正常工作的 QQ 适配器和已放行的测试群。

插件必须实体放在**主程序目录**的 `plugins/LittleFlowerDraw`。目录结构：

```text
MaiBot 工作区/
├── config/                       # 机器人配置
├── data/                         # 机器人数据
├── host/                         # WebUI 宿主注册表
├── plugins/
│   └── LittleFlowerDraw/         # 本插件的实体 Git 仓库
├── src/                          # 主程序源码
├── temp/                         # 临时文件
└── bot.py
```

本项目使用实体目录，不使用目录联接或符号链接；WebUI 插件索引会拒绝解析到插件根目录之外的目录。

首次安装时，在主程序目录执行：

```powershell
git clone https://github.com/suitun/LittleFlowerDraw.git plugins/LittleFlowerDraw
```

已经存在本仓库时直接在当前目录开发，不再克隆第二份。仓库结构：

## 首次启用与验证

1. 打开 WebUI，进入插件管理并刷新页面，查找「小花绘」。
2. 插件默认禁用，在插件管理中启用。Runner 根据配置模型生成本地 `config.toml`。
3. 发送 `小花小花这是 测试角色` 并附图，等待入库成功回复；再发送 `小花小花我要看测试角色`，确认图片能发回。
4. 再用另一张图片登记同名角色，确认收到覆盖回复；到另一个群查看，确认得到新图。
5. 引用一条有图的消息登记另一个角色，验证真实 QQ 引用链路。
6. 在「小花绘 → 插件设置」修改触发词，在「回复配置」修改回复；保存后直接使用新配置，确认无需重启就生效。
7. 在同一模块开启白名单，确认列表外群聊会被可爱地拒绝；再关闭白名单。
8. 在同一模块给登记角色设置一次限额，确认成功登记一次后提示次数用完；再把次数上限调回 `0`。
9. 切到「角色库」模块，确认列表、详情、搜索、上传替换、改名和删除可用。
10. 若新增目录未被运行中的主程序发现，先查看日志；必要时通过 WebUI 重启机器人后再检查。

## 权限、白名单与次数限额

聊天入口只有关键词指令，不再提供 `/小花绘` 等状态命令：

| 指令 | 触发方式 | 默认权限 | 默认次数 |
| --- | --- | --- | --- |
| `登记角色` | 默认 `小花小花这是 {角色名}`，可配置多条模板 | 所有人 | 不限 |
| `查看角色` | 默认 `小花小花我要看{角色名}`，可配置多条模板 | 所有人 | 不限 |
| `角色列表` | 默认 `小花记得谁`，可配置多条模板 | 所有人 | 不限 |
| `帮助` | 默认 `小花绘帮助`，可配置多条模板 | 所有人 | 不限 |
| `自由绘画` | 默认 `小花画{提示词}`，可配置多条模板 | 所有人 | 不限 |

在 WebUI 侧栏的「小花绘」入口中，切到「插件设置」调整权限和白名单，切到「回复配置」调整提示文案：

- **访问白名单**：`admin_qq` 为唯一管理员，默认 `2685275264`；管理员绕过白名单和次数限制。`whitelist_enabled` 关闭时所有群聊/私聊可用，开启后只允许群聊白名单中的群和私聊白名单中的 QQ；列表为空表示该类型全部不可用。
- **指令权限**：每个指令一行，设置权限（`仅管理员` / `所有人`）、次数上限（每人每指令次数，`0` 为不限）和重置间隔（默认 1 天，在到期日 0 点重置）。次数按用户跨群共享；角色库成功才计数，绘图任务入队计数、失败或取消退还。
- **提示文案**：白名单拒绝、仅管理员、次数用完三类回复在「回复配置」中维护；次数提示支持 `{指令}` 和 `{重置时间}`，每种可配置多条并随机抽取，也可单独开启 @ 对方。角色列表文案支持 `{角色数量}`、`{角色列表}`，空库文案不支持占位符。帮助图片的标题和底部提示也可在「回复配置」中修改。

这些设置保存在 `data_dir/webui_settings.json`，保存后立即生效，不需要重载插件。角色库触发词和图片限制在「插件设置」维护；角色库和绘图任务的回复文案在「回复配置」维护。图片太大、格式不支持、图片损坏和其他图片错误分别有可配置文案；大小提示支持 `{实际大小}`、`{大小限制}`，格式提示支持 `{格式}`，其他错误支持 `{原因}`。

WebUI 的角色库操作不受这套聊天权限限制，仍只由 WebUI 登录保护。

## 日常开发流程

1. 在**主程序目录的 `plugins/LittleFlowerDraw` 仓库内**工作。先读 `AGENTS.md`、清单、配置模型和相关接口文档。
2. 查看工作区，已有改动先确认归属。工作区干净且需要获取远程更新时使用快进拉取：

   ```powershell
   git status --short --branch
   git pull --ff-only
   ```

3. 按需求修改插件源码。配置项在 `config_model` 中声明；依赖和宿主能力在清单中声明。
4. 做基础检查，再用宿主 SDK 验证插件导入、组件注册和配置 Schema。下面两条 Python 命令只检查 JSON 和语法，不代表插件已经在 MaiBot 中加载成功：

   ```powershell
   python -m json.tool _manifest.json
   python -m py_compile plugin.py
   git diff --check
   ```

5. 在 WebUI 查看实际加载状态和日志。运行时支持源码与配置热重载；需要时手动重载插件。验证此次修改涉及的行为，确认全局角色共享正确且回复不会发到别的群。
6. 检查差异，仅提交本次相关文件，再同步仓库。按实际改动调整下面 `git add` 的文件列表：

   ```powershell
   git diff
   git add -- plugin.py settings.py role_*.py command_*.py drawing_*.py webui_settings.py webui.json webui _manifest.json README.md AGENTS.md tests
   git diff --cached
   git commit -m "描述本次改动"
   git push origin main
   ```

本机在这个目录改代码，就是在修改运行中的主程序读取的代码，不需要再次复制或从 GitHub 下载安装。

## 更新到另一台运行机器

1. 开发机完成检查、提交并推送。
2. 在运行机器的主程序目录 `plugins/LittleFlowerDraw` 执行 `git status --short --branch`。有本地源码改动时先处理，保留本地配置和数据。
3. 工作区干净后执行 `git pull --ff-only`，再在 WebUI 确认插件重新加载；必要时手动重载。
4. 检查配置能打开、命令能触发，以及本次更新涉及的功能和日志。

自用的 `main` 分支更新不需要创建 GitHub Release 或提交插件市场。`_manifest.json` 中的 `version` 在发布新插件版本时更新；`plugin.config_version` 只在配置结构发生变化时更新，两者不要求每次一起改。

如果需要撤销已经推送的某次改动，使用 `git revert <提交号>` 创建撤销提交，验证后再推送、重载。

## 配置、数据与权限

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `plugin.enabled` | `false` | 是否启用小花绘 |
| `plugin.config_version` | `0.6.0` | 配置结构版本；与插件版本分开维护 |

`config.toml` 由 Runner 生成，只保留启用状态和配置版本；当前源码的默认配置结构版本为 `0.6.0`，与插件版本 `0.9.0` 分开维护。

角色库触发词、图片限制、绘图基础提示词、任务队列、管理员 QQ、白名单和指令权限都在「小花绘 → 插件设置」中维护，角色库/绘图/权限回复在「回复配置」中维护，统一保存在 `data_dir/webui_settings.json`；首次启动会从旧版 `config.toml` 的对应分组迁移。

使用 `send.text`、`send.image` 回复；`chat.open_session` 确保首条请求能建立聊天流；`message.get_by_id` 读取宿主引用历史；`api.get`、`api.call` 调用 SnowLuma 的公开消息和图片查询接口；`webui.claim_upload` 领取 WebUI 上传的图片。

- `assets/`：需要随代码版本维护的固定素材。
- `self.ctx.paths.data_dir/roles.sqlite3`：角色名、首次创建者、单张图片和时间戳。同名覆盖在单个事务内完成，失败会保留旧图；不会把角色名作为文件路径。
- `self.ctx.paths.data_dir/command_usage.sqlite3`：每人每指令的当日次数与 0 点重置窗口。
- `self.ctx.paths.data_dir/webui_settings.json`：触发词、回复、图片限制、权限、白名单、提示文案和后续 WebUI 模块设置。
- `self.ctx.paths.data_dir/drawing_api.json`：绘图 API 的 URL、Token、模型、尺寸和超时。
- `self.ctx.paths.data_dir/drawing_tasks.sqlite3`：任务 ID、队列、状态、历史与退次数标记。
- `self.ctx.paths.data_dir/drawing_tasks/{任务ID}/reference.png`：提交时保存的参考图。
- `插件目录/drawings/`：已生成图片按日期保存；属于运行产物，已加入 `.gitignore`。
- `self.ctx.paths.data_dir/uploads`：WebUI 上传的临时文件，领取并入库后删除。
- `self.ctx.paths.runtime_dir`：临时图片、WebUI 缩略图缓存和可重建文件。

本地配置、环境变量文件、日志、数据库和 Python 缓存均由本仓库 `.gitignore` 排除。

当前支持 PNG、JPEG、WebP、GIF。保存的是通过消息接口实际收到的图片，仍受 QQ 以及 MaiBot 入站图片压缩、体积和 IPC 限制影响，不承诺原始分辨率。网络图片仅从受支持的 QQ 图片 CDN 读取；同机的客户端本地图片路径只信任公开 `get_image` 接口返回的结果。

## 排查未显示或未加载

按以下顺序检查：

1. WebUI 插件列表是否对应本机主程序目录及插件实际安装位置。
2. 主程序目录下的 `plugins/LittleFlowerDraw` 是否为实体目录，且清单和 `plugin.py` 直接位于其中。
3. 名称是否为「小花绘」、ID 是否为 `suitun.little-flower-draw`，清单版本是否使用 `0.9.0`。
4. 清单兼容范围、依赖与 `capabilities` 是否通过实际环境校验。
5. 插件是否只是处于禁用状态，或重载失败后回滚；以主程序日志和 WebUI 实际状态为准。
